Implementation notes — PUN-120 (retention watch)

Spec: Linear PUN-120 (DB canonical + PostHog visual + daily Discord post) · Started: 2026-06-06

Design decisions

Canonical DB computation

apps/web/src/lib/retention.ts — computeRetention(days) over game_events: cohort = anon sessions by first-qualifying-play UTC day; returning = round_started/daily_opened on a later day. Returns per-day cohort size + D1 + D7, with rates null until the window matures. formatRetentionMessage renders a monospace Discord table.

Daily Discord post via cron

apps/web/src/routes/api/cron/retention-report.ts — CRON_SECRET-guarded (same pattern as discord-daily), posts to DISCORD_ALERTS_CHANNEL_ID (staff, not the public daily channel). Scheduled 0 7 * * * in vercel.json. ?force=1 for ad-hoc runs.

PostHog visual leg

Added a HogQL "Retention watch — D1/D7 by cohort day" insight to scripts/posthog/dashboards.ts, mirroring the DB definition (person_id cohorts over the same two events). Applied via the existing apply.ts.

Anon floor caveat baked into the output

The Discord message header and the insight description both state this is a floor (localStorage session resets) and signed-in retention is the true number.

Deviations from spec

None.

Tradeoffs considered

Cron route triggers a routeTree.gen.ts regen

Adding the route required the TanStack router codegen to run (via build) so the new path types in. The regenerated routeTree.gen.ts is part of the change — expected.
