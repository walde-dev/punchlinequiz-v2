Implementation notes — PUN-119 (share→land→signup loop)

Spec: Linear PUN-119 (opaque anon carrier · attribution · stitch-on-signup · reward tease) · Started: 2026-06-06

Design decisions

Two additive tables (migration 0020)

anon_referral_codes (opaque code → sharer session_id, unique per session) and pending_anon_referrals (deferred edges keyed by referee). Both additive — no change to the existing referrals table. SQL: packages/db/drizzle/0020_thick_black_widow.sql.

Opaque code, never the session_id

genReferralCode() mints a 10-char code; mintAnonReferralCode is get-or-create (stable per session). Share URLs carry ?r=<code> (anon) or ?i=<handle> (signed-in), via getShareCarrierFn. The raw session_id (the game_events analytics key) is never exposed.

Deferred attribution + stitch-on-signup

recordPendingReferral (referral.ts): anon code → sharer session → account if it exists (normal edge), else park in pending_anon_referrals. stitchAnonReferralsOnSignup runs from claimHandleFn: it writes a 0-XP anon_xp_claims link (so the session resolves even for 0-XP sharers — closes the "sharer signs up first" gap) and converts parked edges into real referrals rows. Existing confirm-on-activation + reward/cap path is reused unchanged.

Landing capture + event restored

captureReferralFromUrl() (referral-client.ts) reads ?i=/?r=, stores first-touch, returns the token only when newly captured. <ReferralCapture/> in __root.tsx fires referral_landing_viewed once — the event that had fired only once ever.

Reward tease feeds PUN-118

getAnonReferralTeaseFn counts parked edges for the current anon session; SessionGate shows "N already joined from your link — claim them" as the offer subtitle when N>0.

Deviations from spec

None.

Tradeoffs considered

server-only import boundary

First attempt imported getServerSessionId (from log.ts, which top-level-imports react-start/server) and used it in the plain function recordPendingReferral — the build's import-protection plugin rejected it (leaked into the client via the /i route). Fixed by referencing getServerSessionId ONLY inside createServerFn handlers (mirrors anon-xp.ts) and passing refereeSessionId into recordPendingReferral as a param.

Referee-already-active timing

A stitched edge confirms (and pays out) on the referee's NEXT correct answer. If the referee had already gone fully idle, the reward waits until they return. Acceptable for v1; flagging.

Other share surfaces

The carrier is wired into the result-screen share (session-summary). Daily share (daily.tsx) and challenge links (/c) still use their own paths — extend shareUrlFor carrier usage there if you want full coverage.
