Implementation notes — PUN-122 (result-screen share)

Spec: Linear PUN-122 (declutter + de-risk + telemetry; card already exists) · Started: 2026-06-06

Design decisions

Decluttered to PRIMARY "Next bars" + SECONDARY share

In session-summary.tsx: removed the explicit WhatsApp / X / Instagram chips, the Save button and the duplicate Copy button. Primary gold CTA is now onRestart ("Next bars →") — fixes the buried-continue / logo-workaround finding. Share is one secondary action (native share card; copy-link is shown only as the desktop fallback when navigator.share is absent).

Challenge = signed-in upgrade only

Previously a signed-out player got a SignInButton-wrapped "Challenge a friend" (a competing CTA that forced auth for 97% of users). Now the challenge button renders only when isSignedIn; signed-out players just get the share card.

Render + share telemetry

We were blind to real-device render. Added card_render_succeeded / card_render_failed (with elapsed ms) around renderShareCard, and share_completed / share_dismissed around the native share-sheet resolution. share_clicked is kept as the intent signal.

Deviations from spec

None.

Tradeoffs considered

Continue-primary vs share-primary

Recommended share-primary (share is the thing that doesn't happen on its own); user chose continue-primary. Implemented as chosen. The decluttered single secondary share is still a big step up from being lost among 8 CTAs. Tradeoff noted on the ticket: may cap share lift; revisit if 1.5% doesn't move.

Kept Discord card as-is

Per user decision, the DiscordJoinCard stays unchanged on the result screen even though it adds a second "join" surface.
