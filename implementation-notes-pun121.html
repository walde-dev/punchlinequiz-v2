Implementation notes — PUN-121 (acquisition source capture)

Spec: Linear PUN-121 (first-touch persisted + session_started event; full referrer/utm/path) · Started: 2026-06-06

Design decisions

Both storage modes

apps/web/src/lib/acquisition.ts: captureFirstTouch() persists first-touch to pq.first_touch (first-touch wins); <ReferralCapture/> in __root.tsx fires a dedicated full-fidelity session_started event once per tab (sessionStorage guard). The coarse acq_source bucket is also stamped on EVERY event in track.ts for join-free slicing.

Full fidelity + coarse bucket

session_started carries referrer, landing path, utm_source/medium/campaign. Every other event carries just the source bucket (reddit | search | share | direct | internal | referral | <utm_source>). A landing with a ?r=/?i= carrier buckets as share — reinforcing PUN-119.

Deviations from spec

None functionally; see the PII note below (a guardrail on top of the chosen full-fidelity capture).

Tradeoffs considered

Stamp source on all events vs. only the 3 named events

The ticket listed round_started/handle_claimed/share_clicked. Implemented as a single choke-point in logEvent stamping the small bucket on ALL client events — strictly more useful for slicing and cheaper than per-call wiring. The bucket is not PII; full referrer/path stays only on session_started.
