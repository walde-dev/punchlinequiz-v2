Implementation notes — Error Tracking & Observability

Spec: Linear PUN-46..50 (project "Error Tracking & Observability") · Started: 2026-06-02 · Prior notes archived: implementation-notes-referral.html

Stack: TanStack Start + Nitro on Vercel, Clerk auth, Node ≥20, pnpm workspace. Done-bar (from grill): infra-ready + synthetic-verified pre-launch; real-traffic threshold tuning is a post-launch follow-up. No real Sentry DSN / Axiom token / Discord webhook / MCP connection can be provisioned from this environment, so all runtime code is env-gated to no-op when its credential is absent (mirroring the existing track.ts Axiom pattern). The verification gate for code is pnpm typecheck + pnpm build; the remaining account/dashboard steps are listed under Open questions.

Design decisions

Env-gated, no-op-without-credentials everywhere

Client Sentry inits only when VITE_SENTRY_DSN is set (lib/sentry.client.ts); server only when SENTRY_DSN is set (instrument.server.ts); the logger direct-forwards to Axiom only when AXIOM_TOKEN/AXIOM_DATASET are set (lib/axiom.ts, same gate as track.ts). Local dev and the Vercel preview run with zero observability credentials; the feature ships dark until accounts exist.

session_id propagated via the pq_sid cookie (PUN-47)

getSessionId() in lib/track.ts:30 mirrors the localStorage id into a 1-year pq_sid cookie. Server side reads it: getServerSessionId() in lib/log.ts for logs, and sentryScopeMiddleware in lib/sentry-scope.ts for the Sentry session_id tag. This is the join key across Sentry + Axiom + the gameEvents DB. Clerk userId set as Sentry user when signed in.

"Tag key flows" done centrally, not per-route (PUN-47)

Rather than touching every route, flowForPath() in lib/sentry-scope.ts derives a flow tag (challenge_play / daily_submit / admin) from the request path in the global middleware. One place, covers all requests including server fns and API routes.

Sentry server SDK loaded via custom entries; errors-only config

src/server.ts overrides the default TanStack entry: imports ./instrument.server first (init before any request), then wraps the fetch handler with wrapFetchWithSentry. start.ts registers the two global Sentry middlewares + our scope middleware (order documented inline). tracesSampleRate: 0 + browser-noise filters keep the free-tier quota for real errors. Source-map upload (vite.config.ts) is gated on SENTRY_AUTH_TOKEN so only the Vercel build uploads.

Deviations from spec

Sentry packages externalized from the Nitro server bundle

The build (nitro@3-beta + rollup@4) crashed with Cannot read properties of null (reading 'getVariableForExportName') while rendering the server chunk that pulls in @sentry/tanstackstart-react (its export * namespace re-exports). Fix: externalize @sentry/*, @opentelemetry/*, and import/require-in-the-middle from the server bundle via nitro({ rollupConfig/rolldownConfig: { external } }) in vite.config.ts. They resolve at runtime from the traced node_modules. This is also Sentry's recommended state (its Node instrumentation works unbundled). Only affects the server build — the client bundle still bundles @sentry/react normally. Build now green; verified the externalized imports + wrapFetchWithSentry + instrument init are present in .output/server.

Alert rules (PUN-49) are config, documented not coded

Sentry alert rules (new-issue / spike / regression) live in the Sentry dashboard, not the repo. Documented in docs/logging-observability.md → Alerting and docs/observability-runbook.md. No code artifact possible.

Axiom ingest URL + path changed for EU region (post-setup)

The Sentry + Axiom orgs were created in the EU region. Two code/config consequences, both verified against the live APIs: (1) lib/axiom.ts now builds {AXIOM_URL}/v1/ingest/{dataset} (was the deprecated api.axiom.co/v1/datasets/{name}/ingest, which 404s on the edge); AXIOM_URL defaults to https://api.axiom.co and is set to https://eu-central-1.aws.edge.axiom.co in .env. A live test ingest returned {"ingested":1}. (2) Sentry source-map upload must target the EU host via the SENTRY_URL=https://de.sentry.io env var — the plugin's url option isn't on its public type, so env is the supported lever. The app's Axiom token is ingest-only; the MCP/runbook query path needs a query-capable token.

Tradeoffs considered

Client Sentry init via side-effect import vs a custom src/client.tsx

Sentry's docs put client init in a custom src/client.tsx entry. This app has no custom client entry (framework default). Rather than introduce one and risk breaking hydration, init is a guarded side-effect import in router.tsx (import "./lib/sentry.client"), client- and DSN-gated. Browser-tracing/replay integrations are omitted (we run tracesSampleRate 0), so the router reference those wrappers need isn't required — keeping the override unnecessary.

Open questions

Ops steps remaining before this is live (need credentials I can't provision)

(1) Create the Sentry project → set SENTRY_DSN + VITE_SENTRY_DSN (runtime) and SENTRY_AUTH_TOKEN/SENTRY_ORG/SENTRY_PROJECT (Vercel build env, for source maps). (2) Create the Axiom account + punchlinequiz dataset → set AXIOM_TOKEN/AXIOM_DATASET; enable the Vercel → Axiom log drain. (3) Wire the Discord webhook into the Sentry alert rules. (4) Connect Sentry MCP + Axiom MCP for the runbook workflow.

Synthetic verification (the spec's "done" bar) needs the above

Code is typecheck-clean and builds green, but the spec's acceptance — "throw a test error → it reaches Sentry with a source-mapped stack + correct session_id → an alert fires → MCP finds the timeline" — can only be exercised once a DSN and the accounts exist. The worktree also has no .env, so even a local boot needs Clerk/DB env. Recommend running the synthetic check in a Vercel preview deploy with the env set.

Verify @sentry/tanstackstart-react@10.55.0 middlewares behave on this exact runtime

Wiring matches Sentry's v10 manual-setup docs and the installed type surface, but the SDK + nitro@3-beta combo is new. Confirm in a preview deploy that server exceptions actually land in Sentry (not just that the build/typecheck pass). The manual-init fallback (@sentry/node + @sentry/react) noted in PUN-46 remains the escape hatch if not.
