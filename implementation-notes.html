Implementation notes — SEO & Link Surface

Project: PUN SEO & Link Surface (PUN-76..79) · Started: 2026-06-01 · 2 phases · Prior notes archived: implementation-notes-{referral,contributor,profiles}.html

Settled (grilling): .de canonical (.com 301→.de, platform-level); indexable = /artist/$slug catalog pages + SEO infra; NO lyric text on public pages (quiz integrity + copyright); index /, /artist/$slug, /play, /daily, /leaderboard, noindex the rest, Disallow /admin+/api; artist OG = artist photo, default banner elsewhere; MusicGroup+BreadcrumbList on artist, WebSite/Organization on home; dynamic /sitemap.xml. 2 phases: infra → artist pages + sitemap.

Design decisions

P1seo() helper + default OG in root, per-route override via meta dedup

lib/seo.ts seo({title,description,path,image,type,noindex}) returns the TanStack head() {meta,links}. Root route carries default OG/Twitter; child routes call seo() to override — TanStack dedupes meta by name/property/title (deepest wins). Verified in SSR: home shows the home description override + canonical/og:url to https://punchlinequiz.de/.

P1Canonical emitted only when a path is given

seo() adds <link rel=canonical> + og:url only when path is set, so the root default never emits a canonical that would collide with a child's. Indexable routes (/, /play, /daily, /leaderboard, later /artist) pass path; utility routes use noindexSeo() (no path, adds robots noindex,follow).

P1JSON-LD via head() scripts

jsonLd(obj) → {type:"application/ld+json", children: JSON.stringify(obj)} in the route's head().scripts. Home emits WebSite + Organization (verified: two ld+json blocks SSR'd). Artist pages will add MusicGroup + BreadcrumbList.

P1noindex applied per-route, not via robots Disallow

/profile, /submit, /i/$handle, /c/$slug, /u/$handle use head:()=>noindexSeo() (meta robots noindex,follow — verified on /submit). robots.txt only Disallows /admin + /api (server-only) and adds the Sitemap line; app pages are crawlable-but-noindex via meta so link equity still flows (follow).

P2Artist SEO-eligibility = active + ≥1 active bar

lib/artist.ts: listSeoArtists + getArtistPageFn only surface artists with an active playable bar, so no thin/empty pages get indexed or sitemapped. Page content is metadata-only (name, photo, bar count, tags, related artists, play CTA) — verified zero lyric text in the SSR output. MusicGroup + BreadcrumbList JSON-LD + canonical/og:url to .de/artist/$slug all confirmed.

P2Crawl graph: /artists hub + related links + sitemap

/artists hub lists every eligible artist → /artist/$slug; each artist page links to related artists (shared tag); home footer links to /artists, /leaderboard, /daily. Dynamic /sitemap.xml (escaped-dot route file sitemap[.]xml.ts) lists home + static indexable + all eligible artists (verified: 28 URLs, application/xml, absolute .de).

P2Artist meta in German, UI i18n

The head() title/description for artist pages are hardcoded German (canonical audience + .de), while the visible component text uses i18n (DE/EN). Meta lang matches the de-default document.

Deviations from spec

P2Unknown artist = soft 404 (HTTP 200 + noindex), not a 404 status

An unknown/inactive/empty /artist/$slug renders a "not found" component with noindex but still returns HTTP 200 (TanStack route components always 200). Acceptable for SEO (noindex keeps it out of the index). If a true 404 status is wanted, the loader can throw notFound() — flagged as an open question.

Tradeoffs considered

None — followed the settled design.

Open questions

.com → .de 301 is a platform config (not in code)

This build emits rel=canonical + OG url to absolute .de URLs from every page, but the actual .com → .de 301 redirect must be set in the Vercel project's domain settings / DNS. Action item for the user.

SITE_URL is hardcoded to https://punchlinequiz.de

In lib/seo.ts. If the canonical host changes, or you want per-environment base URLs (preview deploys), switch it to an env var. Fine as a constant for now.

Default OG image = /banner-chains.png

Used as the site-wide share image (artist pages use the artist photo). Confirm it works as a ~1200×630 share card; a purpose-built default OG image + dynamic per-page OG cards are the Daily Share Card & Dynamic Link Unfurl project.

Soft 404 on unknown artists

Returns HTTP 200 + noindex rather than a 404 status (see deviation). Say the word if you want a true 404 via throw notFound() in the loader.
